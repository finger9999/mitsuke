# 005. LLM 채점, 비용을 얼마나 아낄 수 있나

2026-11-14 · 관련 파일: [finder/scorer.py](../../finder/scorer.py), [finder/pipeline.py](../../finder/pipeline.py), [config.yaml](../../config.yaml)

## 요구사항

- 1단계: 규칙을 통과한 매물을 LLM이 취향 기준으로 채점, 90점 이상만 알림
- LLM은 저렴한 것으로
- 지금 취향: 울이 무조건 들어간 숏코트
- 걱정: "매물이 많은데 사진까지 다 넘기면 아무리 싼 모델이라도 너무 비싸지 않나?"

## 모델 선택

Claude 모델 중 가장 싼 **Claude Haiku 5.5**(`claude-haiku-5-5`)를 쓴다. 입력 100만 토큰당 $0.10, 출력 100만 토큰당 $0.50 (프롬프트 10만 토큰 이하 기준). 비용을 더 줄이려고 `effort`를 `low`로 둔다.

## 걱정이 맞는지 먼저 쟀다

| 항목 | 측정값 |
| --- | --- |
| 썸네일 크기 | 240×240, 7KB → 이미지 토큰 약 76개 |
| 기준점 130개 중 규칙 통과 | 36개 (28%) |
| 그중 아우터 | 10개 (전체의 8%) |
| 새 매물이 올라오는 속도 | 두 브랜드 합쳐 하루 몇 개 수준 (기준점 매물의 등록 시각 분포와, 등록 후 첫 1시간 동안 새 매물 0개로 추정) |

**사진은 비싸지 않았다.** 메루카리 검색 결과의 썸네일은 240×240이라 이미지 토큰이 약 76개뿐이다. 오히려 판매자 설명(최대 2,000자로 자름)과 채점 기준 프롬프트가 토큰 대부분을 차지한다.

매물 하나 채점 비용 추정 (입력 약 3,000토큰, 생각+출력 약 500토큰 이하):

```
3,000 × $0.10/100만 + 500 × $0.50/100만 ≈ $0.0005  (1원 안팎)
```

추정치라서, 실제 비용은 매물마다 응답의 토큰 사용량으로 계산해 DB(`score_cost_usd`)에 남기고 앱에 이번 달 합계를 보여준다.

## 그래도 넣은 절약 장치

1. **규칙이 먼저 거른다.** 예산·파자마 규칙을 통과한 매물만 LLM으로 간다 (약 28%).
2. **지금 찾는 종류만 채점한다.** `score_categories`(기본: 아우터 12, 31)에 해당하는 매물만 채점하고, 나머지 규칙 통과 매물은 LLM을 부르지 않고 앱 목록에만 올린다. 알림이 필요한 건 숏코트뿐이라서다. 전체의 약 8%만 채점한다.
3. **실행당 상한** `llm_calls_per_run: 30`.
4. **월 상한** `llm_monthly_budget_usd: 1.0`. 이번 달 채점 비용 합계가 넘으면 그달은 채점 없이 목록에만 올린다.
5. 상한에 걸리거나 채점에 실패한 매물도 **목록에는 올린다** (점수 없이, 이유 표시). 놓치지 않게 하려는 설계 원칙이다.

## 채점 설계

- 입력: 썸네일 1장, 제목, 가격, 카테고리 경로, 판매자 설명. 소재(ウール)는 제목보다 설명에 적힌 경우가 많아서 설명을 같이 본다. 설명은 매물 상세 API(004에서 카테고리용으로 찾은 `/items/get`)에서 가져온다. 채점 대상 매물마다 메루카리 요청이 한 번 늘어난다.
- 출력: 구조화 출력(JSON 스키마)으로 `{score, reason}`을 받는다. 형식이 깨질 걱정이 없다.
- 취향 기준은 맥 앱 설정에서 자유롭게 쓴다. "무조건" 조건은 확인될 때만 90점 이상을 주도록 시스템 프롬프트에 규칙을 넣었다. 소재를 알 수 없으면 89점 이하 → 알림 없음, 목록에만.
- 👍👎 피드백(앱 카드의 버튼)은 최근 것을 6개씩 프롬프트에 예시로 넣는다. 텍스트만 넣어서 비용이 거의 늘지 않는다.

## API 키 보관

설계 원칙대로 설정 파일에 키를 두지 않는다. 환경 변수 `ANTHROPIC_API_KEY`를 먼저 보고, 없으면 macOS 키체인(서비스 이름 `mitsuke-anthropic`)에서 읽는다. launchd로 돌 때는 셸 환경 변수가 없어서 키체인 쪽이 필요하다.

## 더 줄이고 싶어지면 (나중 단계)

- 설계 문서 4단계의 **온디바이스 임베딩**(Core ML, Apple Neural Engine): 👍한 매물 사진과 비슷한지 맥에서 공짜로 먼저 걸러, 애매한 것만 LLM으로 보낸다.
- 설명 없이 제목·사진만으로 1차 채점하고, 애매할 때만 설명을 붙여 다시 묻는 2단계 채점.

지금 물량에서는 둘 다 필요 없어 보인다. 실제 비용 기록이 쌓이면 다시 판단한다.

## 확인 상태

- 단위 테스트(가짜 채점기로 알림 기준, 카테고리 제한, 상한, 실패 처리)는 통과.
- **실제 API 호출은 아직 안 해봤다.** API 키를 넣은 뒤 첫 실행 결과로 확인해야 한다.
