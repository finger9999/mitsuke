# 008. 취향은 글이 아니라 예시로 전달한다

2026-11-14 · 관련 파일: [finder/scorer.py](../../finder/scorer.py), [finder/store.py](../../finder/store.py), [finder/images.py](../../finder/images.py), [app/Mitsuke/Sources/Mitsuke/RateView.swift](../../app/Mitsuke/Sources/Mitsuke/RateView.swift)

## 문제

울 숏코트만 채점하다가 "다른 종류의 옷도 좋아할 수 있다"는 요청으로 전체 카테고리를 채점하게 바꿨다. 취향 기준은 두 칸으로 나눴다.

- [알림 받고 싶은 것] 울 숏코트 → 90점 이상, 알림
- [관심 있는 것] 두 브랜드 특유의 디자인이 살아 있는 옷·소품 → 60~89점, 목록에만

결과: 대부분 30~40점에 몰렸고, 상위권(울 퀼로트 85점, 구두 85점)도 왜 높은지 납득하기 어려웠다. 사용자 판단: "내 취향을 정확히 반영하는 게 너무 힘들 것 같다. 벡터 유사도? 근데 옷은 작은 디테일로 취향이 갈려서 유사도만으로도 한계가 있을 것 같다."

## 고민한 선택지

| 방식 | 한계 |
| --- | --- |
| 글로 된 취향 기준 (지금까지) | 옷 취향은 말로 다 못 적는다. 깃 모양, 무늬의 결, 장식이 갈림길인데 미리 적어 둘 수 없다 |
| 벡터 유사도만 | 사진 전체가 "대체로 비슷한지"만 본다. 같은 브랜드 코트는 다 비슷하게 나와서 디테일 차이를 못 가른다 |
| **예시 사진을 보여주고 비교시키기 (선택)** | 유사도는 "무엇과 비교할지" 고르는 데만 쓰고, 디테일 판단은 비전 LLM이 사진을 나란히 놓고 한다 |
| 나만의 분류 모델 (나중) | 라벨이 100개 이상 필요. LLM이 뽑은 디테일 속성 + 사진 특징으로 학습하면 취향이 무엇인지 해석도 된다 |

공통된 결론: **취향은 예시로만 정확히 전달된다.** 어떤 방식이든 👍👎 라벨이 병목이니, 라벨을 쉽게 모으는 화면도 같이 만든다.

## 바꾼 것

### 1. 사진 비교 채점

채점할 때 Gemini에 이렇게 보낸다.

```
사용자가 직접 평가한 비슷한 매물들:
[참고 1] 사용자 👍 좋아함, 그때 AI 점수 50점: ツモリチサト ダブルボタンショートコート … / 레디스 > 아우터 > …
<썸네일>
[참고 2] 사용자 👎 싫어함: センソユニコ ダウンコート … 
<썸네일>
…
─── 이제 아래 매물을 채점한다 ───
<채점할 매물 원본 사진>
검색어 / 제목 / 가격 / 카테고리 / 설명
```

- 참고 매물: 👍 3개 + 👎 2개 (`config.yaml`의 `reference_likes`, `reference_dislikes`).
- 고르는 기준은 지금은 **카테고리가 가까운 순 → 최근 평가 순**이다 (`Store.feedback_references`). 4단계에서 온디바이스 사진 임베딩이 생기면 이 함수의 정렬 기준만 사진 유사도로 바꾼다.
- 시스템 프롬프트에 "참고 사진이 글로 된 기준보다 정확한 근거다. 디테일 단위로 비교하라"를 넣었다.
- "AI 50점 → 사용자 👍"처럼 AI 점수를 같이 보여줘서 AI가 틀렸던 사례를 분명히 한다.
- 채점할 매물은 **원본 사진**(`static.mercdn.net/item/detail/orig/photos/{id}_1.jpg`, 약 75KB)을 보낸다. 썸네일(240×240)로는 디테일이 안 보인다. 참고 사진은 썸네일.
- 같은 참고 사진을 매번 보내므로 사진은 `data/images/`에 캐시한다.

비용: 유료 가격 기준 매물당 약 $0.0005 → **$0.0018** (2원 남짓). 원본 사진과 참고 사진 때문에 늘었지만 여전히 작고, 무료 등급이라 실제 청구는 없다.

### 2. 빠른 평가 화면 (맥 앱)

- 사진을 크게 하나씩 보여주고 ← 👎 / → 👍 / 스페이스 건너뛰기.
- 순서: **AI 점수가 70점 근처인 것부터** (AI가 가장 헷갈리는 구간 → 라벨 하나당 배우는 게 많다).
- 5개마다 **규칙에서 탈락한 매물을 무작위로 하나** 섞는다. 여기서 👍가 나오면 규칙이 놓친 것이라, 3단계 평가에서 재현율을 재는 데 쓴다.

### 3. `reevaluate --rescore`

이미 점수가 있는 매물도 새 방식으로 다시 채점한다. 방식이 바뀔 때 전후를 비교하려고.

## 실수: 캐시 사진을 공개 저장소에 올렸다

`data/images/`를 `.gitignore`에 넣지 않아 매물 사진 5장이 커밋·푸시됐다. 바로 다음 커밋에서 추적을 끊고 무시 목록에 넣었다. 이전 커밋 기록에는 남아 있다.

## 결과: 아직 효과가 안 보인다

`reevaluate --rescore`로 69개를 새 방식으로 다시 채점했다 (유료 가격 기준 $0.147, 무료 등급이라 실제 청구 없음, 2개는 메루카리 상세가 403 → 팔린 매물로 추정).

| | 바꾸기 전 평균 점수 | 바꾼 뒤 평균 점수 |
| --- | --- | --- |
| 사용자가 👍한 3개 | 58 | 58 |
| 사용자가 👎한 16개 | 39 | 41 |

👍와 👎를 가르는 정도가 거의 그대로다. 점수 이유도 여전히 "좋아하는 브랜드라서" 같은 일반론이 많다.

원인으로 보이는 것:
- **👍가 3개뿐이다** (👎는 16개). 비교할 "좋아한 사진"이 거의 없어서, 사진 비교가 할 일이 없었다.
- 평가된 매물 수가 적어 이 비교 자체도 통계적으로 의미가 약하다. 제대로 된 비교는 3단계 평가 하네스에서 한다.

다음 행동: 빠른 평가 화면으로 👍를 더 모으고, 사용자가 좋아하는 옷 예시를 받아 첫 👍로 넣는다. 👍가 20~30개쯤 모이면 다시 비교한다.
