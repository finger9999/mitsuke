# 014. Hugging Face 패션 이미지 모델로 취향 맞히기

2026-11-15 · 관련 파일: [evals/hf_experiment.py](../../evals/hf_experiment.py), [evals/reports/](../../evals/reports/)

## 질문

사용자: "평가 같은 건 Hugging Face 모델을 가져와서 하는 건? 너무 복잡한가?"

Hugging Face 모델은 평가 도구라기보다 **또 하나의 채점기**다. 012에서 만든 평가(👍👎를 정답으로 한 분리도 AUC)로 Gemini와 나란히 비교할 수 있다. 맥에서 무료로 돌고, 설계 문서 4단계(온디바이스 임베딩)를 앞당기는 일이기도 하다.

## 실험

- 모델 (Hugging Face에서 확인한 패션 특화 이미지 모델 두 개):
  - `Marqo/marqo-fashionSigLIP` (open_clip, 다운로드 약 43만)
  - `patrickjohncyh/fashion-clip` (transformers, 다운로드 약 36만)
- 입력: 라벨 181개(👍 15 / 👎 166)의 썸네일 240×240. 맥 GPU(MPS)에서 벡터로 바꿈.
- 방식 세 가지. 모두 **한 개 빼고 평가**(매물 하나를 맞힐 때 그 매물 라벨은 안 씀):
  - 중심 유사도: 👍 사진들과의 평균 유사도 − 👎 사진들과의 평균 유사도
  - kNN: 가장 비슷한 라벨 매물 5개의 👍 비율
  - 로지스틱 회귀: 벡터로 👍/👎를 가르는 작은 선형 모델
- 의존성은 `requirements-ml.txt`로 분리했다 (PyTorch 등 몇 GB, 파이프라인에는 필요 없음).

## 결과

| 방식 | AUC (012와 같은 99개) | 사진 한 장 | 비용 |
| --- | --- | --- | --- |
| **Gemini 사진 비교** (012) | **0.801** | 수 초 | 매물당 약 3원 (무료 등급) |
| Marqo FashionSigLIP · 중심 유사도 | 0.668 | 20ms | 0원 |
| FashionCLIP · 중심 유사도 | 0.668 | 7ms | 0원 |
| Marqo · 로지스틱 회귀 | 0.637 | 20ms | 0원 |
| FashionCLIP · kNN | 0.611 | 7ms | 0원 |
| Gemini 글 기준만 (012) | 0.590 | 수 초 | 매물당 약 1원 |

라벨 전체(181개) 기준으로는 Marqo 로지스틱 회귀 0.694, 중심 유사도 0.688이 가장 높았다. 전체 표는 `evals/reports/20261115-2021-hf.md`.

### 1차 거름망으로 쓰면?

Marqo 중심 유사도로 LLM 전에 거른다고 했을 때:

| 👍를 얼마나 살리나 | LLM 전에 거를 수 있는 👎 |
| --- | --- |
| 100% | 18% |
| 90% | 43% |

## 해석

- **사용자의 예상이 맞았다.** 사진 전체의 비슷함만 보는 방식(0.67 안팎)은 글 기준만(0.59)보다는 낫지만, 디테일을 비교하는 Gemini 사진 비교(0.80)에는 못 미친다.
- 대신 **공짜이고 빠르다** (사진 한 장 7~20ms). 결과도 매번 같다.
- 1차 거름망으로는 아직 약하다. 👍를 하나도 안 놓치려면 👎를 18%밖에 못 거른다. 지금은 Gemini가 무료 등급이라 거를 이유도 크지 않다.
- 👍가 15개뿐이라 숫자가 흔들린다. 특히 로지스틱 회귀처럼 학습하는 방식은 라벨이 늘수록 좋아질 여지가 크다.

## 결정

- 채점은 **Gemini 사진 비교를 유지**한다.
- 이미지 모델은 나중에 두 곳에 쓴다.
  1. Gemini에 보여줄 **참고 사진을 고르는 기준**: 지금은 "카테고리가 가까운 순"인데, 실제로 생김새가 비슷한 👍👎를 고르게 바꾼다. 효과는 012 평가로 잰다.
  2. 👍가 50개쯤 모이면 1차 거름망으로 다시 잰다.
- Core ML 변환과 ANE(신경망 칩) 측정은 실제로 파이프라인에 넣을 때 한다.
