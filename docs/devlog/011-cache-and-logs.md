# 011. 사진 캐시와 로그가 계속 쌓인다

2026-11-14 · 관련 파일: [finder/images.py](../../finder/images.py), [main.py](../../main.py)

## 발견

반나절 운영 후 점검해 보니:

- `data/images/`에 사진 236장, **21MB**. 울 숏코트 검색(시간당 약 20개) 때문에 이대로면 한 달에 1GB 가까이 쌓인다.
- `logs/mitsuke.log` 210KB + `logs/launchd.err.log` 68KB. 같은 내용이 두 파일에 중복으로 쌓이고, 대부분이 HTTP 요청 한 줄씩이었다.

## 왜 사진을 남겨 뒀나

Gemini는 호출 사이에 기억이 없다. "이 사용자는 이런 걸 좋아한다"를 알려주려면 👍👎한 매물 사진을 **매 채점마다 다시 보내야** 한다 (008). 그래서 참고 사진은 남아 있어야 한다.

하지만 용량 대부분은 참고용 썸네일(약 7KB)이 아니라, 채점할 매물의 **원본 사진**(약 75KB)이었다. 원본은 채점이 끝나면 다시 쓸 일이 없다.

사진을 한 번만 보고 버리는 방법도 있다. 👍👎할 때 사진을 임베딩 벡터나 디테일 설명 글로 바꿔 두는 것이다. 하지만 비교 채점은 실제 사진이 가장 정확하고 썸네일은 100개에 1MB 안팎이라, 썸네일은 남기기로 했다. 벡터는 4단계에서 따로 만든다.

## 고친 것

- **사진 정리** (`images.cleanup`, 매 실행 끝에):
  - 원본 사진: 하루 지나면 삭제
  - 썸네일: 👍👎한 매물은 계속 보관, 나머지는 7일 뒤 삭제
  - 처음 정리에서 166장을 지워 21MB → 712KB.
- **로그**:
  - 1MB가 넘으면 `mitsuke.log.1~3`으로 밀어내고 그보다 오래된 건 버린다 (`RotatingFileHandler`).
  - 화면 출력은 터미널에서 직접 실행할 때만. launchd로 돌 때는 `launchd.err.log`에 똑같은 내용이 쌓이기만 했다.
  - `httpx`, `httpx2`, `google_genai`의 요청 단위 로그는 WARNING 이상만 남긴다.
