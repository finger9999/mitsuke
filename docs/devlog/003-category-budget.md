# 003. 아우터만 예산을 다르게 주기

2026-11-14 · 관련 파일: [finder/sources/categories.py](../../finder/sources/categories.py), [finder/filters.py](../../finder/filters.py), [config.yaml](../../config.yaml)

## 요구사항

- 검색 브랜드: tsumori chisato, sensounico
- 아우터는 7,000엔 이하, 상의·하의·소품 등 나머지는 3,000엔 이하 (처음에 7만/3만 엔으로 잘못 전달돼 한 번 고침)
- 파자마는 제외, 정크(고장품)는 상관없음

## 검색어 정하기

같은 브랜드를 일본어와 영어로 검색해 최신 60개가 얼마나 겹치는지 봤다.

| 브랜드 | 일본어 | 영어 | 겹침 |
| --- | --- | --- | --- |
| tsumori chisato | ツモリチサト 60개 | tsumori chisato 60개 | 60개 (완전히 같음) |
| sensounico | センソユニコ 58개 | sensounico 58개 | 48개 |

tsumori chisato는 메루카리가 표기를 같은 브랜드로 묶어주는 듯해서 하나만 쓴다. sensounico는 일부만 겹쳐서 둘 다 검색한다. 겹치는 매물은 DB에서 ID로 한 번만 처리된다.

## 아우터를 어떻게 구분할까

제목에 「コート」「ジャケット」 같은 단어가 있는지로 볼 수도 있지만, 「ジャケット柄」처럼 엉뚱하게 걸리거나 「ブルゾン」처럼 빠뜨리기 쉽다. 검색 결과에 매물마다 `categoryId`가 붙어 오길래 이걸 쓰기로 했다.

문제는 붙어 오는 게 **가장 아래 단계** 카테고리라는 점이다. 예를 들어 롱코트는 `149`(ロングコート)로 오는데, 이게 아우터(`12` レディース > ジャケット/アウター)인지 알려면 부모를 따라 올라가야 한다.

```
149 ロングコート → 12 ジャケット/アウター → 1 レディース
```

그래서 규칙에는 위 단계 카테고리를 적고, 매물의 조상 중에 그 카테고리가 있는지 본다.

```yaml
category_price_max:
  12: 7000   # レディース > ジャケット/アウター
  31: 7000   # メンズ > ジャケット/アウター
```

## 겪은 것: 카테고리 목록이 일부 빠져 있다

메루카리 웹이 쓰는 카테고리 목록 API(`/services/master/v1/itemCategories`)로 트리를 받아 저장했다. 1,324개가 왔다.

그런데 실제 매물 128개를 돌려보니 **카테고리 38종이 목록에 없었다.** 예를 들어 `1426`(카디건 > 반소매), `3093`(셔츠·블라우스 > 민소매) 등. `pageSize`, `showDeleted` 옵션을 줘봐도 새 카테고리는 나오지 않았다.

매물 상세 API(`/items/get`)를 열어보니 이유가 보였다. 메루카리가 **다단계(N-tier) 카테고리**로 옮겨가는 중이고, 상세 응답에는 새 체계의 전체 경로가 들어 있었다.

```
1426 半袖:
  3088 ファッション > 1 レディース > 11 トップス > 129 カーディガン・ボレロ・アンサンブル > 1426 半袖
```

새 체계에서도 `1`(レディース), `11`(トップス), `12`(アウター) 같은 예전 id는 그대로 쓰인다. 그래서 빠진 카테고리만 채우면 기존 규칙이 그대로 동작한다.

새 체계 전체 목록을 주는 API를 몇 개 추측해 봤지만 찾지 못했다.

## 해결: 모르는 카테고리는 매물 상세로 한 번만 알아낸다

1. 기본 트리는 목록 API 스냅샷(`finder/sources/mercari_categories.json`, 저장소에 포함)
2. 새 매물 중 트리에 없는 카테고리가 있으면, 그 카테고리 매물 **하나**의 상세를 불러 경로를 알아낸다
3. 알아낸 경로는 `data/mercari_categories_learned.json`에 쌓는다. 같은 카테고리는 다시 묻지 않는다
4. 상세 호출이 실패하면 기본 예산(3,000엔)을 적용하고 다음 실행에서 다시 시도한다

처음 128개를 학습시킬 때 상세 호출이 38번 있었고, 그 뒤로 모르는 카테고리는 0개가 됐다.

## 파자마 제외

카테고리 `186`(ルームウェア/パジャマ > パジャマ)을 제외하고, 다른 카테고리로 올린 파자마도 잡도록 제목 키워드 「パジャマ」도 같이 뺀다. 같은 부모 아래 `190`(ルームウェア)은 파자마가 아니라서 남겨뒀다.

## 남은 문제

- **브랜드와 상관없는 매물이 섞인다.** 예: 「tsumori chisato PAUL&JOE 猫 タオルハンカチ」(실제 브랜드는 PAUL&JOE). 규칙으로 거르기 애매해서, 1단계 LLM 채점에서 거를 예정이다.
- **취향은 아직 안 본다.** 지금 규칙은 가격과 파자마만 보기 때문에, 예산 안에 들어오는 두 브랜드 새 매물(기준점 기준 약 27%)이 모두 알림으로 온다.
