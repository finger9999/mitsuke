# 006. 마음에 드는 아우터가 "기준점"에 묻혀 있었다

2026-11-14 · 관련 파일: [finder/pipeline.py](../../finder/pipeline.py), [finder/store.py](../../finder/store.py)

## 증상

사용자: "아우터이고 예쁘고 예산도 안 넘었는데 기준점으로 탈락한 애가 있어. 왜야?"

## 원인

설계 문서의 원칙 "첫 실행은 기준점만 저장한다"를 문자 그대로 구현했었다. 검색어의 첫 실행에서 이미 올라와 있던 매물을 `seeded` 상태로 저장만 하고 **규칙 검사도 채점도 하지 않았다.** 그래서 앱 기본 목록(통과 매물만)에는 안 보이고, "탈락·기준점 포함"을 켜야 회색 "기준점" 딱지를 달고 보였다. 사용자 눈에는 탈락처럼 보였다.

DB를 확인해 보니 기준점 128개 중 아우터이면서 예산 안인 매물이 9개 있었다. 예: ¥4,380 ツモリチサト ダブルボタンショートコート, ¥5,900 センソユニコ テーラードジャケット ウール.

원칙의 원래 목적은 "알림이 한꺼번에 쏟아지지 않게"였다. 평가까지 건너뛸 이유는 없었다.

## 고친 것

1. **첫 실행도 평가한다.** 규칙 검사와 채점은 평소처럼 하고, 알림만 보내지 않는다. 그러려고 매물 하나를 처리하는 코드를 `Evaluator`로 분리해서, 일반 실행과 첫 실행과 다시 평가가 같은 코드를 쓴다.
2. **`python main.py reevaluate` 명령.** 예전 방식으로 평가 없이 저장된 기준점 매물을 다시 평가한다. API 키가 있으면 점수가 없는 통과 매물도 채점한다. 알림은 보내지 않는다.
3. **다시 평가해도 기록이 보존된다.** 저장(`Store.add`)을 upsert로 바꿨다. 이미 있는 매물은 평가 결과만 바꾸고, 처음 본 시각과 👍👎 피드백은 그대로 둔다.

## 결과

기준점 128개를 다시 평가: 탈락 93개(예산 초과), 통과 35개. 이제 위의 아우터들도 앱 기본 목록에 보인다. API 키를 넣고 `reevaluate`를 한 번 더 돌리면 이 중 아우터가 채점된다.
