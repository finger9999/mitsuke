# 015. 실행 하나가 23시간 동안 멈춰 있었다

2026-11-15 · 관련 파일: [finder/scorer.py](../../finder/scorer.py), [main.py](../../main.py), [config.yaml](../../config.yaml)

## 증상

사용자: "23시간 전 상품까지만 나오고 그 뒤 상품이 앱에 안 보인다."

## 원인 찾기

```
$ launchctl print gui/$UID/com.mitsuke.run
    state = running
$ ps -axo pid,lstart,etime,command | grep "main.py run"
57116  Sat Nov 14 21:25:50 2026   23:26:15  ... main.py run
```

전날 21:25에 시작한 실행이 **23시간째 끝나지 않고** 있었다. launchd는 같은 작업이 돌고 있으면 다음 실행을 시작하지 않아서, 그동안의 매시간 실행이 전부 건너뛰어졌다.

마지막 로그는 "새 카테고리 …" 몇 줄이었고, 그다음 단계는 Gemini 채점이다. macOS의 `sample` 명령으로 프로세스가 어디서 멈췄는지 봤다.

```
_ssl__SSLSocket_read → SSL_read_ex → ssl3_read_n    (863/863 샘플 전부)
```

TLS 소켓에서 응답을 읽으며 무한정 기다리고 있었다. 메루카리 요청(httpx)은 20초 시간 제한이 있으니 범인은 Gemini 호출이다. `google-genai` 클라이언트는 **기본 시간 제한이 없다.** 맥이 잠든 사이 연결이 끊겼는데, 끊긴 줄 모르고 영원히 기다린 것으로 보인다.

## 고친 것

1. 멈춘 프로세스를 종료하고 다시 실행했다.
2. **Gemini 호출에 60초 시간 제한** (`HttpOptions(timeout=60_000)`). 다시 실행하자 바로 `504 DEADLINE_EXCEEDED`가 한 번 찍혔다. 시간 제한이 실제로 작동한다는 뜻이다.
3. **재시도**: 무료 등급은 503(과부하)이 잦아서, 429·503·504는 5초부터 늘려 가며 3번까지 다시 시도한다 (`HttpRetryOptions`).
4. **실행 전체에 안전장치**: 한 번 실행이 25분(`max_run_minutes`)을 넘으면 `SIGALRM`으로 끊고 실행 기록에 "시간 초과로 중단"을 남긴다. 어떤 이유로든 멈춘 실행이 다음 실행을 막지 못하게.
   - 끊기면 그때까지 처리한 매물은 저장돼 있고, 못 본 새 매물은 DB에 없으니 다음 실행이 새 매물로 다시 집는다.

## 배운 것

외부 API 호출에는 시간 제한을 꼭 둔다. 그리고 주기 실행에는 "한 번 멈추면 다음도 다 막힌다"는 실패 방식이 숨어 있어서, 개별 호출의 시간 제한과 별개로 실행 전체의 상한도 둔다.
